# 상품 데이터 연동 서버 (선택 기능)

이 디렉터리는 Android 앱의 '실제 상품 조회' 기능에 연결할 수 있는 서버의 기본 구조입니다. 실제 쇼핑몰 API 이용 권한과 자격증명은 아직 제공되지 않았습니다. 다만 서버 코드에는 공공 가격조사 CSV와 네이버 쇼핑 검색 API 연결 기능이 구현되어 있습니다. 사용자가 데이터 파일 또는 유효한 API 자격증명을 제공해야 실제 결과가 나옵니다.

## 실행

Node.js 20 이상에서:

```bash
node server/index.mjs
```

기본 포트는 8787이며, `PORT` 환경변수로 변경할 수 있습니다.

- `GET /health`: 서버 상태
- `GET /api/foods?q=검색어`: CSV 또는 네이버 쇼핑 검색을 연결한 경우 `candidates` 배열 반환. 별도 상품 공급 API를 연결한 경우 `products` 배열 반환. 아무 공급원도 없으면 한국소비자원 공식 2026-08-28 공개 가격동향 중 검증한 만두 4종의 과거 집계가격만 반환하며, 해당 없는 상품은 빈 결과를 반환합니다. 이는 실시간 연동이 아닙니다.
- `FOOD_UPSTREAM_URL`: 합법적으로 접근 가능한 상품 공급 API URL. 검색어는 `q` 쿼리로 전달합니다.
- `FOOD_API_TOKEN`: 공급 API에 필요한 경우 서버 환경변수로만 설정. 앱에는 입력하지 않습니다.
- `CONSUMER_PRICE_CSV_PATH`: 한국소비자원 참가격 CSV 파일의 서버 내 경로. 조사 시점의 가격이며 실시간 판매가가 아닙니다.
- `CONSUMER_PRICE_CSV_URL`: 한국 공공데이터포털(`data.go.kr`)에서 직접 내려받을 수 있는 HTTPS CSV 파일 URL. 서버가 6시간 동안 캐시하며 재조회합니다. 다운로드 페이지나 메타데이터 JSON 주소는 사용할 수 없습니다. `CONSUMER_PRICE_CSV_PATH`가 있으면 로컬 파일을 우선합니다. 실제 다운로드 주소는 데이터 제공 조건을 확인한 후 설정해야 하며, 기본값은 비어 있습니다.
- `NAVER_CLIENT_ID`와 `NAVER_CLIENT_SECRET`: 네이버 쇼핑 검색 API 자격증명. 둘 다 필요하며 서버 환경변수로만 설정합니다. 사용량 제한과 이용조건은 네이버 정책을 확인하세요.
- 공급원 우선순위: `CONSUMER_PRICE_CSV_PATH`가 설정되어 있으면 CSV를 먼저 사용하고, 그 외에 네이버 자격증명이 있으면 네이버 검색을 사용합니다. 별도 `FOOD_UPSTREAM_URL`이 설정되어 있으면 해당 공급 API를 사용합니다. 운영 전 코드의 우선순위와 설정을 확인하세요.
- `ALLOWED_ORIGIN`: 허용할 브라우저 Origin (선택). Android WebView의 로컬 파일 출처는 배포 환경에서 별도 검토가 필요합니다.

공급 API는 `{ "products": [...] }` JSON을 반환해야 합니다. 상품은 `name, price, size, measure(g/mL), rating(0~5), reviews, seller, url` 형식을 따릅니다. 공급자의 실제 응답 필드가 다르면 별도의 매핑 구현이 필요합니다.

이 서버는 상품 데이터를 스크래핑하지 않고, 제공 권한이 있는 API만 연결하도록 설계했습니다. 운영 전 HTTPS 배포, 인증·속도 제한, 데이터 사용조건, CORS 정책 검토가 필요합니다.

공급업체 연동 시 요청·응답 예시와 필드별 검증 규칙은 [`SUPPLIER_API.md`](./SUPPLIER_API.md)를 참고하세요.

## 운영 전 확인 사항

- `FOOD_UPSTREAM_URL`은 자격증명과 URL 조각(`#...`)이 없는 HTTPS 주소만 허용합니다. 공급업체가 요구하는 인증 토큰은 `FOOD_API_TOKEN`에만 보관하세요.
- `ALLOWED_ORIGIN`을 사용하는 경우 경로나 쿼리가 없는 정확한 HTTPS Origin(예: `https://example.com`)만 지정하세요. `*`, HTTP 주소, 경로가 붙은 주소는 서버 시작 시 거부됩니다.
- `ALLOWED_ORIGIN`을 비워 두면 서버는 `Access-Control-Allow-Origin` 헤더를 내보내지 않습니다. Android WebView가 로컬 `file://` 페이지에서 HTTPS 서버에 접근할 때는 실제 앱 환경의 CORS 동작을 별도로 검증해야 합니다. 임의로 `*`를 허용하는 방식으로 우회하지 마세요.
- `/health`의 `providerConfigured:true`는 공급 API 주소가 설정됐다는 뜻이며, 상품 조회 성공을 의미하지 않습니다. `/api/foods?q=...`를 호출해 HTTP 200과 `products` 배열을 확인해야 합니다.
- 공급업체가 허용한 API만 사용하며, 공급업체 데이터의 가격·평점·원산지·원재료는 별도 검증되지 않은 정보로 취급합니다.

배포 및 실제 점검 절차는 [`DEPLOY.md`](./DEPLOY.md)를 참고하세요.

## API 결과와 앱 자동 등록의 차이

공공 CSV와 네이버 쇼핑 검색은 상품명·가격·판매처 등 일부 정보만 제공하므로, 앱의 `candidates` 미리보기로 표시됩니다. 실제 판매가와 조사 가격을 혼동하지 마세요. 용량·평점·리뷰·품질 근거를 임의로 채워 종합평가 상품에 등록하지 않습니다. 네이버 API 연결에는 별도 발급받은 자격증명이 필요하며, 무료 이용 가능 범위는 제공업체 정책에 따라 달라집니다.

## 네이버쇼핑 후보 가격 비교

`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 서버에 설정하면 `/api/foods?q=저지방%20우유` 요청에 대해 네이버 쇼핑 검색 API를 사용합니다(별도 공급 API와 CSV가 설정되지 않은 경우). 서버는 상품명에 검색 단어가 모두 포함되는 결과만 남기고, 동일 상품명·판매처·가격·URL 중복을 제거한 후 표시 가격 오름차순으로 최대 30개를 돌려줍니다. 이 결과는 `candidates`에 들어가며 상품의 용량이나 품질 점수를 임의로 추정하지 않습니다.

API 키 발급, 사용 한도, 배포용 HTTPS 주소는 사용자 계정 및 서비스 설정이 필요하므로 저장소 코드만으로 자동 개통되지 않습니다. 자격증명은 GitHub 소스 코드나 앱 설정에 기록하지 말고 서버 환경변수 또는 배포 환경의 비밀 설정에만 보관하세요.
